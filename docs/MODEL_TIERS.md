# Model tiers — one choice, every provider, always the newest model

Status: v1, 2026-10-27. Owner: Kahf Labs. Adopted by Qasd and Mizwala now; Raqeeb adopts it when its planner takes a model
setting. The pinned table is [`catalog/model-tiers.json`](../catalog/model-tiers.json).

## Why

Kahf Labs, 2026-10-27: "create a drop-down list low: haiku, medium: sonnet, and high: opus, all always take the latest,
and that has to be work in chatgpt, gemeni as well, and Raqeeb in future."

Model names change every few months (Claude went 4.5 → 5 → 5.5; OpenAI renamed its tiers to Sol, Terra, Luna and
Astra; Google moved to Gemini 4 Argon). A product that names a model in code is out of date the day a new one ships,
and Mizwala's first review agent already was (`claude-sonnet-4-5`, `gpt-4o-mini`). So products name a **tier**, never
a model, and resolve the tier to the provider's newest model at run time.

## The choice the person sees

One drop-down, the same words in every product (Arabic first where the product is):

| Tier | English | Arabic | Meant for |
|---|---|---|---|
| `low` (default) | Fast | سريع | Everyday briefs, short reviews, high volume. Cheapest |
| `medium` | Balanced | متوازن | Planning, longer reviews |
| `high` | Best | الأدق | Hard reasoning, when quality matters more than cost |

Next to it, the provider (Claude, ChatGPT, Gemini) and the person's own key. The resolved model ID is shown in small
type under the drop-down ("now: claude-haiku-5-5"), so the person always knows what runs.

## Tiers per provider

| Tier | Claude (Anthropic) | ChatGPT (OpenAI) | Gemini (Google) |
|---|---|---|---|
| `low` | newest Haiku | newest Luna | newest Flash-Lite |
| `medium` | newest Sonnet | newest Terra | newest Flash |
| `high` | newest Opus | newest Sol | newest Pro |

`high` is each provider's strong everyday model, not its most expensive one (Claude Fable, OpenAI Astra and Pro
variants are left out), matching "high: opus".

## Resolving a tier (every product does exactly this)

1. **Ask the provider, with the person's key.** List its models and keep those matching the tier's `pattern` in
   `model-tiers.json`; skip any matching `exclude`. Pick the newest:
   - Anthropic: `GET /v1/models` (paginated); newest `created_at`.
   - OpenAI: `GET /v1/models`; newest `created`.
   - Google: `models.list`; prefer the tier's `alias` (`gemini-flash-latest`, `gemini-pro-latest`) when the list has
     it, else the highest version number in the name.
2. **Cache** the result for 24 hours per provider and tier (device-local, never in backups or exports).
3. **Fallback**: if listing fails (offline, key without list permission, timeout of 5 s), use the cached value, then
   the `pinned` ID from the table bundled with the app.
4. **Self-heal**: if a request fails with "model not found" or "deprecated", drop the cache, resolve again once, and
   retry once. Never loop.

The person may also pin an exact model ID ("Advanced → exact model"); a pinned ID is never changed by resolution.

### In the SDKs

- **Dart** (`dart/lib/src/model_tiers.dart`): `ModelResolver.resolve(vendor, tier, key)` does steps 1–3 and
  `ModelResolver.run(...)` step 4. `TierCache` is the device-local store (Qasd keeps it in shared preferences).
  The table it falls back to is generated from `catalog/model-tiers.json` (`tool/sync_model_tiers.dart`); a test
  fails if they differ.
- **Kotlin** (`kotlin/kahf-connect/.../ModelTiers.kt`): the same API (`ModelResolver.resolve`, `run`, `modelGone`,
  `TierCache`), with the table generated by `./gradlew :kahf-connect:syncModelTiers`. `AiClient.kt` makes the
  requests below on plain Ktor, with no vendor SDK.

## Requests that keep working when the model changes underneath

Because the model ID changes without a code change, requests use only what every current model accepts:

- **Claude:**
  - Use the official Anthropic SDK where one exists for the language. On Dart, use raw HTTP; on Android, use the Java
    SDK or raw HTTP.
  - Never send `temperature`, `top_p` or `top_k`: they return 400 since 2026-10-21. Never prefill an assistant turn,
    and never force `tool_choice` `any` or `tool`.
  - Omit `thinking` (adaptive is the default) and set `output_config.effort` explicitly: `low` for the `low` tier,
    `medium` for `medium`, `high` for `high`. Use `output_config.format` for JSON.
  - Check `stop_reason` before reading content, and handle `refusal`.
- **OpenAI and Gemini:** each provider's current recommended API, from its own docs. Never an "OpenAI-compatible"
  shim for another provider.
- Keys stay on the device (or in the product's encrypted key store), never in backups, exports, logs or URLs.

## Keeping the table current

`catalog/model-tiers.json` holds, per provider and tier, the `pattern` for step 1 and a `pinned` ID for step 3,
with the date each was last checked. When a provider renames a family (as OpenAI did), only the pattern changes. The
pinned IDs marked `verified: false` were read from the provider's public docs on 2026-10-27, not yet from a live
`/models` call; the first product to resolve them with a real key records the result here.

Later: publish the table, signed with the catalog key, at a public address, so products pick up a renamed family
without an app update.
